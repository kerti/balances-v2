# Zone: IMPORT

Bulk ingestion — the widest single write surface in the app, and the one most
able to corrupt many rows at once. The flow has a shared spine in
`internal/importcreate/importcreate.go` (`Run` / `RunWithLedger`): parse the
workbook, resolve the Detail-sheet conventions, validate every row, and gate a
write behind an explicit `mode=commit`. Parsing lives in the DB-free
`internal/snapshotimport/importer.go`; the atomic writes are the per-group
`CreateXWithSnapshots` / `…AndLedger` repo methods. The defining risk is a
**partial or misclassified** import: a preview that promises one thing and a
commit that does another, or a batch that writes half its rows before failing.
The per-month snapshot upsert is already INV-SNAPSHOTS-04, and cross-household
rejection is INV-TENANCY/INV-SNAPSHOTS-04 — this zone guards the
preview/commit/atomicity machinery on top of them.

| ID | Invariant | Source | Severity |
|----|-----------|--------|----------|
| INV-IMPORT-01 | Preview/commit parity, dry-run is a no-op: `mode=preview` (default) validates and reports the same insert/update (and ledger) counts a commit would apply, but never calls the commit func — it writes nothing | ADR-0022 | Critical |
| INV-IMPORT-02 | All-or-nothing: a workbook carrying any field or row error is refused at commit (422) with the commit func never called, and a mid-batch repo failure (e.g. a snapshot row whose shape doesn't match the subtype) rolls the whole transaction back — no position, tag, or snapshot left behind | ADR-0022 | Critical |
| INV-IMPORT-03 | Create-with-snapshots fan-out is atomic and complete: one transaction writes the position, its resolved tag (or untagged when none), and every seeded snapshot together — across all five position groups and the investment ledger variant | ADR-0022 | Critical |
| INV-IMPORT-04 | Detail-sheet identity resolution: a sole-owner email resolves to a household user id and a tag name to a tag id; an unresolvable email or tag is a `FieldError` (blocks `would_create`, fails commit 422) — never a silent write and never a 500 | ADR-0022 | High |
| INV-IMPORT-05 | Per-row parsing is strict: a malformed month/number/value-shape is a `RowError` (not a silent skip or a coerced value), genuinely blank rows are skipped, a duplicate month is flagged, and an exported workbook round-trips back through Parse unchanged | ADR-0022 | High |
| INV-IMPORT-06 | The client drop zone accepts only a spreadsheet: a file is `.xlsx` by extension (case-insensitive) or by the spreadsheet MIME, a multi-file drop takes the first, a non-xlsx drop is rejected `invalid` and an empty drop is `empty` — a frontend-native guardrail before any upload (the backend's "not a spreadsheet is 400" is the server-side twin) | ADR-0022 | Medium |
| INV-IMPORT-07 | Import entry points are ownership-gated: the template-download/meta and import paths resolve a position only within the caller's household; an unknown or cross-household id is `ErrNotFound` (404) — never a template leak or a write into another household's position (the import-side face of INV-TENANCY) | ADR-0022, ADR-0005 | High |
| INV-IMPORT-08 | Create-import preview names the duplicates it would make (#828, audit BUG-03): a clean preview reports the household's existing positions with the same subtype and the same display name — case-insensitive, trimmed — plus, for a bank account, the same account number; terminated positions match (a closed account is still the same account), soft-deleted rows and other households' positions never do, and a different name or account number is no match. The lookup runs in SQL under the caller's `household_id`, only on a clean preview (never on commit), and a match never blocks `would_create` — a duplicate can be legitimate | ADR-0022, ADR-0005 | High |
| INV-IMPORT-09 | The create-import dialog surfaces a match without blocking it (#828): the preview names the position (name, masked account number, snapshot count); when the preview carries a match it shows an amber notice — "same name" or "and number" — listing each match by its name, masked number, "(closed)" if terminated and the date it was added (with the time when two matches share a date), each linking to that position's detail page, and **Create anyway** commits exactly as the plain Create does; with no match there is no notice and the button stays **Create** | ADR-0022 | Medium |
| INV-IMPORT-10 | Snapshot import never writes an unchanged month (#829): a file row whose every stored field equals the month's live snapshot — amount, currency, quantity / price per unit / accrued interest where the shape has them, statement date and note — is counted `unchanged`, separately from `to_insert` (new month) and `to_update` (replaced), in the preview and the commit alike, for all four snapshot groups and all three shapes. It creates no row, archives none and does not touch the live row (same id, same `updated_at`); only a changed month is archived and re-inserted. Decimals compare by value after rounding to the column's scale (`100.00` equals the stored `100.0000`, never string-compared), dates by calendar day, and an absent note equals an empty one. A month whose only row is archived is new, not unchanged. Re-importing a position's own export is therefore all-unchanged | ADR-0022, ADR-0058 §1 | Critical |
| INV-IMPORT-11 | Both import dialogs check a file the moment it is chosen (#829): picking or dropping a `.xlsx` runs the dry-run preview at once, there is no Check file button, and the single action (**Import** for snapshots, **Create** / **Create anyway** for a new position) stays disabled until that preview is clean; picking another file re-runs the preview, errors show on pick, and a non-`.xlsx` is refused without calling the server. The native file control is visually hidden but reachable (a label opens it), and the chosen filename is shown exactly once | ADR-0022 | Medium |
| INV-IMPORT-12 | The snapshot-import preview reports the three outcomes (#829): "N new months, M replaced, K unchanged", each count pluralised and a zero count left out ("1 replaced, 26 unchanged"). **Import** is enabled only when something would be written (new or replaced > 0); when every month already matches the preview says "Nothing to import — every month already matches" and Import stays disabled; a file with no rows keeps its own "no rows found" message | ADR-0022 | Medium |
